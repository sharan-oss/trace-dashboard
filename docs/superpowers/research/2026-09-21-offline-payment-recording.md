# Recording out-of-platform payments — what the best products do (research, 2026-09-21)

Input to `docs/superpowers/specs/2026-09-21-record-external-payment-design.md` and ADR 004. Every claim carries its source; where official docs were silent it says so.

## Products

**Stripe.** The simple Dashboard path ("Change invoice status → Paid") is a lossy, **irreversible** status flip ([support](https://support.stripe.com/questions/marking-an-invoice-paid-out-of-band)). The good path is the **Payment Records API**: `report_payment` takes amount (integer minor units + currency), `initiated_at`, outcome, `payment_method_details`, `processor_details[type]=custom`; refunds are *reported* separately, partials allowed; attempts form an **append-only event log** ([payment-records](https://docs.stripe.com/payments/payment-records)). Since the 2025-03-31 API, invoices carry a `payments` array and `amount_paid_off_stripe` ([changelog](https://docs.stripe.com/changelog/basil/2025-03-31/add-support-for-multiple-partial-payments-on-invoices)). Overpayment becomes customer credit; an invoice with attached payments cannot be voided/edited ([partial-payments](https://docs.stripe.com/invoicing/partial-payments)). Idempotency keys: client-generated UUIDv4, ≤255 chars, **never PII**, replayed response incl. failures, error on same-key-different-params ([idempotent_requests](https://docs.stripe.com/api/idempotent_requests)). "Stripe does not support merging customers" — verify before create ([support](https://support.stripe.com/questions/can-i-merge-multiple-customers-into-one)).

**Chargebee.** The cleanest published schema of an offline-payment form: `transaction[amount]`, `[payment_method]` (bank transfer / cash / check / ACH / SEPA; custom methods via support), `[date]`, `[reference_number]`, `comment` (≤300 chars); supports idempotency; surplus → `excess_payments` credit ([record-an-invoice-payment](https://apidocs.chargebee.com/docs/api/invoices/record-an-invoice-payment), [offline_payments](https://www.chargebee.com/docs/payments/2.0/offline-checkout/offline_payments)). Reversal is a **new transaction** ("record an offline refund"), gated to Owner/Admin ([record-an-offline-refund](https://apidocs.chargebee.com/docs/api/transactions/record-an-offline-refund), [invoice-operations](https://www.chargebee.com/docs/billing/2.0/invoices-credit-notes-and-quotes/invoice-operations)). Activity log records *which team member* did what ([KB](https://www.chargebee.com/docs/billing/2.0/kb/platform/how-to-find-which-team-member-performed-a-certain-activity-on-chargebee-app)).

**Zoho Books.** Fields: customer, amount received, payment date, deposit-to, payment mode (editable list), reference number, notes, attachments; one receipt can split across invoices; payments are freely editable/deletable — the permissive counter-example ([record-payment](https://www.zoho.com/us/books/help/invoice/record-payment-for-invoice.html), [other-actions](https://www.zoho.com/us/books/help/payments-received/other-actions.html)). Bulk = CSV import with a sample template ([import-export](https://www.zoho.com/us/books/kb/payments/import-export.html)).

**QuickBooks Online.** Payment method with inline "add new"; reference no.; Undeposited Funds separates *when the customer paid* from *when the money hit the bank* ([Intuit](https://quickbooks.intuit.com/learn-support/en-us/help-article/bank-deposits/whats-undeposited-funds-account/L6Jan3iRK_US_en_US)).

**Razorpay.** No way to record a non-Razorpay payment; it is a gateway, not a ledger ([dashboard](https://razorpay.com/docs/payments/payments/dashboard/)). UPI payments expose `method`, `vpa` and `acquirer_data.rrn` — the 12-digit UTR is the natural reconciliation reference ([fetch-payment-expanded-upi](https://razorpay.com/docs/api/payments/fetch-payment-expanded-upi/)).

**Polar / Paddle / Lemon Squeezy.** Merchants of record; none records operator-entered cash. Paddle's "sales-assisted invoice" is Paddle-mediated bank transfer ([Paddle](https://developer.paddle.com/concepts/sell/sales-assisted-invoice/), [Polar](https://polar.sh/docs/features/orders)).

**Creator platforms.** TagMango has an open, unshipped request for off-platform enrolment ([ideas board](https://ideas.tagmango.com/b/xmn6e50l/feature-ideas/user-migration-for-payment-outside-tag-mango) — non-official); Graphy bills revenue share on manual enrolments ([help](https://us.help.graphy.com/support/solutions/articles/1060000121079-why-is-this-invoice-being-raised-backend-enrolment-charges-explained-)). None captures *how* the money moved, who collected it, or a UTR — that is the wedge.

## Patterns

- **Money input:** never `type="number"`; `inputmode="decimal"`; currency prefix `aria-hidden`; tolerate a re-typed prefix ([GOV.UK text input](https://design-system.service.gov.uk/components/text-input/), [Vercel guidelines](https://vercel.com/design/guidelines)). Integer minor units in storage; `tabular-nums` in display.
- **Validation timing:** on submit, not on blur/keystroke; error summary at the top that takes focus; keep what was typed; always validate server-side ([GOV.UK validation](https://design-system.service.gov.uk/patterns/validation/), [error summary](https://design-system.service.gov.uk/components/error-summary/)).
- **Dates:** default today, date-only, never a JS-only picker ([GOV.UK dates](https://design-system.service.gov.uk/patterns/dates/)).
- **Customer picker:** Base UI `Combobox` has documented async-search and "Creatable" examples ([base-ui.com](https://base-ui.com/react/components/combobox)); Stripe's "Add customer (or press N)" ([invoicing/customer](https://docs.stripe.com/invoicing/customer)); Linear's one-keystroke scoped pickers ([docs](https://linear.app/docs/search)).
- **Feedback:** success verb mirrors the button ("Record payment" → "Payment recorded"), `aria-live="polite"`, Undo/void with a safe window rather than a confirm dialog ([Geist toast](https://vercel.com/geist/toast), [Vercel](https://vercel.com/blog/teaching-agents-product-design-at-vercel)).
- **Next.js 16 mutations:** Server Functions; verify auth *inside* every function (they are reachable by direct POST); `useActionState` pending; revalidate before redirect ([mutating-data, 16.3.x](https://nextjs.org/docs/app/getting-started/mutating-data), [data-security](https://nextjs.org/docs/app/guides/data-security)).
- **Supabase:** insert policies use `with check`; supabase-js has no multi-statement transactions — use a `security invoker` function via `rpc()` so RLS still applies inside; `raise exception` rolls back ([RLS](https://supabase.com/docs/guides/database/postgres/row-level-security), [functions](https://supabase.com/docs/guides/database/functions)).

## Synthesis — what this feature adopted

Integer paise · decimal `inputmode` with tolerated ₹ · Chargebee's field set (customer, amount, date, method, reference, note ≤300) · Indian method list (GPay, PhonePe, UPI, bank transfer, cash, cheque, other) with a method-aware reference hint (UTR) · submit-time validation with a focused error summary · Base UI async Combobox with a Create row and a pre-create "already exists" warning · UUIDv4 idempotency key per submission **plus** a soft same-day-same-amount duplicate warning (the Ritu case) · one `security invoker` RPC for customer+payment · void-only corrections with recorder/reason kept on the row · provenance label "GPay · recorded by hand". Deferred: partial payments/credit balances, CSV import, method list editing.
